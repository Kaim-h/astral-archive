## Findings

- **Book fidelity:** current public main `5d52486c40070d498270801640ebab58d2e871c0` retains Book.qml blob `d4eab2e3e62660123c1cedeff9dbb2cd1784015d` and application Shelf.qml blob `7febfda49329eedc1805a421a4097a54f97b68a3`. S18r3's bookArt uses uniform panel-coloured spines, fixed bands, one rotated title and a static ribbon path. It omits per-app cover, inscription orientation/labels, ornament styles/band counts, running/focused distinction, ribbon visibility/end/length, count marks and the native ribbon's curved hover behaviour. Restore faithful flat spine appearance from current application data and Book.qml; retain separate application IDs, fixed book dimensions and independent board support. For B8 a static readable state-indicating bookmark is a proposed bounded fallback, not an authorization to redesign ribbon movement. Preserve existing native implementation pending separate owner-approved bookmark design work. Lighting Lab remains authoritative for the support board only; do not revert current books to its historical art or 3D experiments.
- **Menu length:** actual Browse root 11 actions; Arrange root six; Appearance replacement menu five. It is not a lateral submenu: showMenu replaces the existing menu at its original position on click, no hover-open or left/right navigation. At 500x400 Browse root was 384px high with 436px scroll height. Proposed shared root (arrangement-first ordering in Arrange): Shelf dimensions, Add furniture, Grid and snapping, Appearance (direct inspector), Undo (one-level two-action flyout until unified history is defined). Existing toolbar controls mode. Rename remains Frame, with contextual shortcut where useful. Move study-only bulk preview commands out of the primary menu; actual Cubby activation remains entry, not cycling. Keep contextual rack/fixture/file menus short and relevant.
- **Long property selectors:** family policy 11, independent field family 11, field emblem up to 13, furniture catalogue 8, selected object 17 in current sample, add support 7 observed, shelf glazing 7, local glazing 8, backing field selector up to 16. Already dropdowns; retain them, group Elemental options with flat optgroups, use searchable selection for growing object/field lists where useful, filter supports by compatible type (do not treat collision-invalid as accepted). Preserve four-visible graphical emblem picker rather than a text-only list. Five tabs and shorter lists need no extra nesting. Appearance panel can open directly to the relevant tab, with shared tabs accessible. Use one-level lateral flyouts only for grouped commands, hover/pointer plus keyboard Right/Left/Enter and touch/click, bounded positioning and focus return; ordinary value dropdowns remain deliberate selection controls, not accidental hover edits.
- **Confirmed transaction defect:** in Arrange, right-click Browser book, open Geometry and support, type X=615 (initial 620), change Selected to Editor and back without Preview geometry. X returns to 620 without warning. arrSelection.onchange re-renders before flushing the current numeric candidate. Validate and stage valid edits before changing selection; invalid values must preserve the existing target and show feedback, not silently discard. This is inconsistent with the accepted implicit-commit rule.
- **Confirmed backing-field issue:** Advanced/Edit independent fields, Add panel twice: both new panels occupy x=24,z=24,w=180,h=180; panelError returns empty. It checks only bounds/minimum size/opacity, not field-field intersections. Existing index refers to non-overlap for independent fields. Reconcile with owner-approved intended behavior: default placement should avoid identical overlaps; if deliberate artistic overlays are allowed they need explicit semantics, not accidental duplication. Backing is still independent of furniture collisions.
- **Context scope issue:** from Cubby-local glazing, clicking Frame switches to Shelf-wide appearance but retains Cubby Preview state/Geometry buttons and local glazing target. Separate global appearance and local Cubby scope or label the scope consistently; ensure edits affect the intended object. Avoid misleading Cubby header/actions. Browse direct contextual access and Arrange geometry-first menus should remain.
- **Known limitations, not new regressions:** separate appearance/arrangement Undo histories, first outside canvas click dismisses without activating underlying object; app removal unplaces book without a general app placement picker; full holder drag/swap, native dynamics, dimension-aware navigation and Bestiary secondary fang remain as earlier reference ledger. No new physics implementation required here.
