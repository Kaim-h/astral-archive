# Scroll seals, purpose and metadata disclosure

**Status:** browser-prototype tooltip layout direction; synthetic sample data, not a verified filesystem metadata backend.

A wax seal and embossed icon identify **file purpose**, separately from its **physical artifact family** and separately from a hex wall's user-selected paint.

| Purpose | Visual direction | Caution |
|---|---|---|
| Ordinary document | Muted brown, quill | Not a file-type guarantee |
| Code/script | Muted blue-grey, tools | Not an execution permission |
| Configuration | Amber, gear | Not an authority marker |
| System/protected | Restrained deep red, shield | Not proof of permissions or danger |
| Logs/diagnostics | Slate, lens or line marks | Not a filesystem privilege |
| Other/fallback | Neutral | Preserve accessible icon/text |

**Hover:** wax seal at left; full filename **including extension** to its right; last-modified date below. No redundant extension row; hover never lifts or moves the object.

**Click:** expand the same card with descriptive type, optional extension, added/imported date, size and full path. Explain “added” as first indexed/imported unless a real birth timestamp is available. Escape or repeated click collapses.

Other file artifact forms (audio record, framed media, spreadsheet ledger, font tablet, compressed archive satchel, 3D sculpture, scientific instrument) may optionally have a **compact scroll fallback** with a type-specific icon; don't make a compact audio scroll look like a code-purpose scroll solely because they share a cylinder.

Future customization of seals, pigments, insignia or parchment edges is optional. Essential settings must remain discoverable through ordinary settings, not gated behind a secret workshop. Information is never conveyed by color alone; seal rendering must not change actual file permissions.
